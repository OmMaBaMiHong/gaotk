# Token 银行：复用账号与渠道流程

2026-09-25，用户澄清并确认实施。直接在原目录 main 开发，提交推送 gaotk/main，仅部署本地验收。

## 已确认需求

1. 删除上一版重复账号管理、独立添加弹窗、独立创建/授权/导入流程和平台单组规则。复用原账号组件、服务与存储，后台增加所属用户列和筛选。
2. C 端 Token 银行复用现有添加、授权、导入、重新授权、账号管理、统计能力，只管理自己的账号；服务器自动绑定当前用户。所有原支持平台沿用已有能力，不另限为三平台。
3. 管理员控制分组、价格、代理、倍率与调度。C端不提交管理配置；导入也不得借此操作别人的账号或全局代理。
4. 原渠道配置增加储蓄分成与接收分组。管理员指定各平台接收分组，授权账号自动加入匹配组；之后沿用原账号多分组能力，不再强制一个账号只有一个分组。
5. 按实际请求的分组/渠道沿用原计价和扣费。金额10，用户分8、平台分2。已有账号统计成本即使为6也不影响分账，不先扣成本再分利润。
6. 成本、计价、默认估算、历史金额快照保留原功能。C端展示自己账号的成本、用量、使用记录、分成和到账收益。不增加用户采购费用、包月成本或摊销模型。
7. 收益自动增加站内余额；独立分账策略、原子账本和幂等保留。渠道配置默认用户80%，管理员可调整并指定收款Admin。
8. 文案用Token银行、Token储蓄、储蓄收益，不叫出租。不包含提现、利息、借贷、额外计价系统。

## 实现边界

- accounts只保留新增owner_user_id。原status/schedulable控制暂停。影子账号追溯凭据父账号的归属。
- 原账号组件默认admin调用，显式用户作用域切换到受限入口；底层仍调用原创建、授权和导入服务。
- 使用原channel.features_config.token_savings保存 enabled、owner_share_bps、admin_user_id、receiving_group_ids；不维护第二套平台规则表。
- 本人使用记录按供货account_id过滤，再复用原查询；只返回该账号计价/用量数据，不回传消费方身份、API Key、IP、会话或提示词。
- 每笔结算保留实际渠道、分成比例、金额快照，重试不重复入账；原计费算法不变。
- 前向迁移撤销旧单组限制及重复账号字段，保留已有账本历史，原迁移文件不篡改。

## 验收标准

- 原管理员添加/导入/授权可用，C端调用同一流程；跨用户操作与管理参数伪造被拒绝。
- 同平台自动接收、多分组与跨渠道按实际请求分账；错平台分组被拒绝。
- 消费10/成本6，分成8/2；重复、并发、事务失败、历史改价与原扣费回归通过。
- 本地真实API、数据库、前后端构建和页面验收后提交推送，重建本地Docker。
