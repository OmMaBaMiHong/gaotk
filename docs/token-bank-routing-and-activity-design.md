# Token 银行：分组接收与收益动态建议

2026-09-25。基于代码与线上只读核查，并按用户后续澄清修订。收益展示已实现并完成本地 Docker 验收，代码提交 3a1f56ad4，尚未发布线上；套餐准入与单组优先级为已对齐的后续改造规则，尚不等于当前代码已支持。延续 token-bank-design.md 的账号、渠道和独立分账复用方案。

## 分组由管理员配置，C 端只授权账号

C 端不提供分组选择。添加页显示平台、账号授权方式，以及只读的接收分组、分成比例；后台按平台匹配管理员已经配置的接收分组。已有账号创建、授权、导入、编辑服务继续复用。

当前逻辑：渠道 features_config.token_savings.receiving_group_ids → 筛选启用且平台相同的分组 → 创建原 accounts 记录并绑定当前用户 → 写入原账号与分组关系。一旦配置多个同平台接收分组，新账号会加入全部匹配组。C 端创建时传入的 group_ids 会被覆盖，编辑时不能改分组。

配置变更影响之后的添加；已有账号不会因此自动迁移，应由管理员在原账号管理中批量调整。一个账号可以绑定多个分组，按实际请求所属分组、渠道计费及分账。

建议第一步只配置 DeepSeek 普通组与启笔月卡这两个已经匹配的平台组，无需新增账号体系或分组选择器。混合月卡保留原模型路由；若后续开放自动接收，必须在原渠道接收配置中明确平台到混合组的对应关系，不能直接取消平台检查。

没有配置对应接收组的平台应在添加页就显示“暂未开放，等待平台配置”，不让用户完成授权后才遇到保存失败；不自动落到默认组或其他平台组。

平台匹配与成本准入分别处理。平台相同不等于账号成本相同，也不证明填入的凭据有效；应复用原授权与连接测试验证，成本、倍率和利润门由管理员维护。GPT 的 0.8 售价、30% 毛利口径仍待用户确认，不能把原成本倍率过滤当作储蓄分账后的净利润保证。

## 月卡分账口径

当前结算基数为 BalanceCost + SubscriptionCost。月卡调用按额度消耗金额参与分账，并非按月卡购买款实时摊分。月卡售价、赠送额度及使用率会影响平台实际收益；绑定月卡前需确认接受该既有口径，不在本方案内另建摊销或结算系统。

## 收益展示：顶部一行广播与排行榜

用户确认：Token 银行顶部使用一行滚动广播，附“收益榜”入口，点击用原弹窗展示累计到账收益前 10 名。不使用默认收起的储蓄动态，不增加个人公开开关，不提供提现。后台原系统设置增加总展示开关，默认关闭；有真实数据后管理员可以开启。

数据直接读取原 account_revenue_ledger 已提交的 owner_amount，与站内余额入账保持同一口径。排行榜按同一用户多个账号合计，广播取近期真实到账。服务端脱敏用户名，不输出用户 ID、完整姓名、邮箱、账号凭据、余额、消费者资料。无收益时显示空态，不生成模拟播报。金额复用现有 USD 站内计价单位，不换汇，也不冒充可提现现金。

广播每 60 秒更新数据，页面隐藏或卸载后停止刷新；总开关关闭时接口不返回榜单和广播明细。使用现有卡片、图标、按钮、弹窗和暗色样式，不另造页面体系。

## GPT 套餐准入与接收优先级（已确认方向，待实现）

用户明确：只有一个默认接收组；匹配多个组时，只加入管理员设置的接收优先级最高的一组。此前“加入所有匹配组”的建议撤回。优先级代表平台运营排序，不把瞬时调用量或不同模型单价直接当作账号收益排名。

平台相同只完成第一层检查。GPT Free、Plus、Pro 各档不能只凭名称或用户填写的 plan_type 匹配。后端必须复用原 OAuth 交换、上游刷新和套餐查询取得可信套餐，再筛选满足平台、账号类型、套餐条件的接收组。Pro 5x 与 Pro 20x 如不能可靠区分，不应默认当作同档。

创建、JSON 导入、重新授权都要经过同一校验；账号套餐降级或更换授权后，还要重新检查现有分组准入。未知套餐不进入要求 Pro 的组；没有合格接收组时明确提示暂未开放对应套餐，不落到高价组。管理员维护原渠道配置与分组，C 端只看到识别出的套餐和只读接收结果。

现有漏洞边界：C 端凭据白名单包含 plan_type；JWT 解析本身不验签；无刷新凭据的 RefreshAccountToken 分支可能保留旧 plan_type。因此不能仅新增一个 plan_type 字符串比较就宣称防止普号进入 Pro。线上 GPT 储蓄接收尚未开启，待可信识别与分组规则闭环后启用。

## 验收边界

- 当前平台隔离仍保持；后续新增套餐校验通过后，只选择优先级最高的一个合格接收组。
- 未开放平台在授权前提示；原管理员账号管理仍能按已有权限配置多分组。
- 原有账号迁移明确列出受影响账号，不把接收配置保存当作迁移完成。
- 月卡按既有额度口径分账，重复请求不重复入账；成本和售价不因收益展示变化。
- 广播及榜单只取真实成功账本；服务端脱敏；总开关关闭不返回明细；页面不可见后停止刷新。
